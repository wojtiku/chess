# What architecture and replacement stages support the agreed learning loop?

Labels: wayfinder:grilling
Type: grilling
Status: open
Blocked by: 03, 06, 07, 09

## Question

Choose the content/runtime, validation, presentation, selection, and learner-record boundaries needed by the agreed product. Decide what is precomputed versus runtime, any engine/AI/network dependencies, how a content item is versioned independently of progress, what existing foundations can be reused, and how old learning behavior is replaced rather than indefinitely duplicated.

Set a staged replacement policy with observable acceptance gates, compatibility expectations, and explicit treatment of existing domain documentation and ADRs. This ticket resolves architectural trade-offs and handoff requirements; it does not implement the architecture or substitute for the final specification. If a concrete UI or logic uncertainty still blocks the decision, create a focused prototype ticket rather than guessing.
